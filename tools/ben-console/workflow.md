# On-demand conversations

Use this workflow when the user asks to talk with Ben or try a behavior through the console. The user task and any optional behavior instructions define the conversation; there is no predefined evaluation suite or grading step.

1. Read the user task and behavior instructions. Choose the initial messages and any synthetic users or channels needed for that task.
2. By default the console reuses persisted dev state in `logs/`, following the checkout's shared symlink. Allow only one Ben process per shared state directory. Before console takeover, stop dev Ben only with session authorization or when needed under the project instructions; the console does not do this automatically. Own a console process in this checkout using `pnpm --silent console`. It runs this checkout's application code and prompts against a local gateway. A running console is never an attachment to production Ben. Keep stdin open, send `{"op":"start"}` with any needed settings, and wait for the start result with `status: "ready"`. Use `fresh: true` only when fresh state is explicitly requested; it starts empty in an OS temporary directory. Save `stateDirectory`, `stateMode` and the absolute artifact paths, including `transcriptPath`. Existing persisted files do not restore an active in-memory conversation.
3. Inject the first message with the appropriate user and channel. Use `@Ben` or `ping: true` to wake him. Read actual deliveries and choose subsequent messages or personas based on what Ben says and the user's task. Give him room to respond before choosing the next follow-up. A message command result only acknowledges injection; it does not mean Ben has finished responding.
4. Read the actual tool calls, results and reply/wait/sleep outcomes alongside messages in `conversation.md`, with one compact list line per message or event. Inspect `session.log` or `trace.jsonl` for diagnostics and operational status deliveries when needed to understand behavior. Use `inspect` for local messages, recognized persisted state files and usage scoped to this artifact session. The console never saves or emits system prompts, prompt snapshots, full model requests/turns, provider histories or hidden reasoning.
5. Send `{"op":"stop"}` and wait for the stopped result. Shutdown drains in-flight work and persistence; it can take as long as an active model request. Stop only the console process you own, leaving live Ben alone.
6. Show the compact readable conversation from `conversation.md`, preserving the actual messages, speakers, tool calls/results and lifecycle outcomes. Include brief observations tied to the user task and links to the transcript and relevant diagnostic artifacts. Distinguish observed behavior from your interpretation.

Modify prompts, restart after changes, or repeat a conversation only when the user authorizes that work. Repeating normally reuses `logs/`; explicitly request `fresh: true` for an empty temporary session. Preserve earlier artifacts. Automated offline tests must always use temporary state. See the [console README](README.md) for commands, directory settings, budgets and lifecycle details.
